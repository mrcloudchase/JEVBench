# ML-systems related work: composing model calls into decision architectures, and evaluating model confidence

Scope note: bibliographic details below were checked against the arXiv API (export.arxiv.org) on 2026-10-18 unless marked **[unverified: from memory]**. Venue strings come from the arXiv "comments"/"journal_ref" fields when present. Numbers are quoted from abstracts or primary pages.

## Q1. Anthropic "Building effective agents" and similar pattern taxonomies (OpenAI, LangGraph)

### Takeaway
Anthropic (Dec 19, 2024) separates *workflows* (fixed code paths) from *agents* (the LLM steers itself) and names one building block (the augmented LLM) plus five workflow patterns: prompt chaining, routing, parallelization (sectioning / voting), orchestrator-workers and evaluator-optimizer. LangGraph's docs copy this taxonomy almost exactly. OpenAI's guide uses a coarser split: single-agent vs multi-agent (manager vs decentralized). Our five structures (single, chained, parallel, orchestrator-worker, evaluator-optimizer) come straight from Anthropic's list but leave out "routing" as its own structure. In our framing a route is a decision rule whose action is "which unit runs next", so it lives in rules, not wiring.

### Cited Findings
- Citation: Erik Schluntz and Barry Zhang (the page shows "Erik S. and Barry Zhang"), "Building effective agents," Anthropic, December 19, 2024. — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- Workflows: "systems where LLMs and tools are orchestrated through predefined code paths." Agents: "systems where LLMs dynamically direct their own processes and tool usage." — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- Augmented LLM: "The basic building block of agentic systems is an LLM enhanced with augmentations such as retrieval, tools, and memory." — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- Prompt chaining: "decomposes a task into a sequence of steps, where each LLM call processes the output of the previous one." Recommended when the task "can be easily and cleanly decomposed into fixed subtasks." — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- Routing: "classifies an input and directs it to a specialized followup task." — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- Parallelization, sectioning: "Breaking a task into independent subtasks run in parallel." Voting: "Running the same task multiple times to get diverse outputs." — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- Orchestrator-workers: "a central LLM dynamically breaks down tasks, delegates them to worker LLMs, and synthesizes their results." — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- Evaluator-optimizer: "one LLM call generates a response while another provides evaluation and feedback in a loop." — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- Agents: "typically just LLMs using tools based on environmental feedback in a loop." — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- Design advice: "we recommend finding the simplest solution possible, and only increasing complexity when needed." Developers should "start by using LLM APIs directly." The page now notes that much of the tooling it describes has changed since December 2024. — [Anthropic](https://www.anthropic.com/research/building-effective-agents)
- OpenAI, "A practical guide to building agents" (PDF, no date on the extracted pages; generally dated 2025 **[date unverified]**). "Agents are systems that independently accomplish tasks on your behalf." Apps that "integrate LLMs but don't use them to control workflow execution—think simple chatbots, single-turn LLMs, or sentiment classifiers—are not agents." An agent has three core components: model, tools, instructions. — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- OpenAI orchestration patterns: "Single-agent systems, where a single model equipped with appropriate tools and instructions executes workflows in a loop" and "Multi-agent systems, where workflow execution is distributed across multiple coordinated agents." Multi-agent splits into the *manager pattern* ("a central LLM—the 'manager'—to orchestrate a network of specialized agents seamlessly through tool calls") and the *decentralized pattern* ("agents can 'handoff' workflow execution to one another… a one way transfer"). In the manager pattern, graph edges are tool calls; in the decentralized pattern they are handoffs. The guide recommends "an incremental approach." — [OpenAI PDF](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)
- LangGraph "Workflows and agents" docs list the same patterns: LLMs and augmentations, prompt chaining, parallelization, routing, orchestrator-worker, evaluator-optimizer, agents. They say "Workflows have predetermined code paths… Agents are dynamic and define their own processes and tool usage." The page wording mirrors Anthropic's. — [LangChain docs](https://docs.langchain.com/oss/python/langgraph/workflows-agents)

### Inferences
- Anthropic's taxonomy is about control flow, and every pattern's node is a *generative* LLM call. Our framing changes the node: it becomes a typed decision unit that returns a belief, plus a separate rule. The patterns stay as wiring. This is the main conceptual difference to state.
- Anthropic's "voting" is the closest analogue to our parallel panels, and OpenAI's manager pattern is the closest analogue to orchestrator-worker. Our finding that same-family panels are not independent bears directly on voting (see Q4).
- Anthropic's routing and OpenAI's handoffs both bury the decision inside the LLM call. We make it an explicit rule over a belief, and Wei Sun (2026, Q2) argues for the same separation.

### Gaps
- No primary date found for the OpenAI PDF (the extracted text has none). The LangGraph page has no visible date or version.
- Anthropic's page names no first author in full. "Erik Schluntz" is from memory; the page shows "Erik S."

## Q2. Compound AI systems and LM programs (BAIR, DSPy, LM Cascades, LMQL, LangGraph)

### Takeaway
The compound-AI line (Zaharia et al. 2024; DSPy; LMQL; Dohan et al.'s LM Cascades) treats model calls as program components and the program as the thing to design and optimize. The nearest 2026 framing to ours is Wei Sun, "Decision-Centric Design for LLM Systems" (arXiv 2604.00414), which explicitly separates "decision-relevant signals" from the policy that maps them to actions, the same split as our belief and rule.

### Cited Findings
- Citation: Matei Zaharia, Omar Khattab, Lingjiao Chen, Jared Quincy Davis, Heather Miller, Chris Potts, James Zou, Michael Carbin, Jonathan Frankle, Naveen Rao, Ali Ghodsi, "The Shift from Models to Compound AI Systems," BAIR Blog, Feb 18, 2024. — [BAIR](https://bair.berkeley.edu/blog/2024/02/18/compound-ai-systems/)
- A compound AI system combines multiple interacting components (several model calls, retrievers, tools), unlike a single statistical model. Supporting numbers: Databricks found 60% of LLM applications use RAG and 30% use multi-step chains. AlphaCode 2 generates up to 1M candidates and reaches about the 85th percentile. Medprompt exceeds GPT-4 by 9% on medical exams. Gemini CoT@32 scores 90.04% on MMLU vs GPT-4 5-shot 86.4%. Tripling training budget lifts a coding model only from 30% to 35%, while sample-and-test reaches about 80%. Named challenges: design space, optimization (non-differentiable components), operation (monitoring and debugging). — [BAIR](https://bair.berkeley.edu/blog/2024/02/18/compound-ai-systems/)
- DSPy: Khattab, Singhvi, Maheshwari, Zhang, Santhanam, Vardhamanan, Haq, Sharma et al. (13 authors), "DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines," arXiv:2310.03714 (Oct 2023); ICLR 2024 **[venue unverified: from memory]**. Pipelines are "text transformation graphs" with declarative modules, and a compiler optimizes them for a metric. Compiled programs beat standard few-shot prompting "generally by over 25% and 65%" (GPT-3.5, llama2-13b-chat) and expert demonstrations by 5–46% and 16–40%. — [arXiv 2310.03714](https://arxiv.org/abs/2310.03714)
- Language Model Cascades: Dohan, Xu, Lewkowycz, Austin, Bieber, Gontijo Lopes, Wu, Michalewski et al. (12 authors), arXiv:2207.10342 (Jul 2022), spotlight at the Beyond Bayes workshop, ICML 2022. Compositions of LM calls "are probabilistic models" and can be written as graphical models / probabilistic programs over string-valued random variables. The paper casts chain of thought, verifiers, STaR, selection-inference and tool use as "language model cascades." — [arXiv 2207.10342](https://arxiv.org/abs/2207.10342)
- LMQL: Luca Beurer-Kellner, Marc Fischer, Martin Vechev, "Prompting Is Programming: A Query Language for Large Language Models," arXiv:2212.06094, PLDI 2023. It introduces "Language Model Programming," which mixes text prompting, scripting and *constraints over model output*, with an inference procedure that cuts expensive LM calls. — [arXiv 2212.06094](https://arxiv.org/abs/2212.06094)
- Chen, Davis, Hanin, Bailis, Stoica, Zaharia, Zou, "Are More LLM Calls All You Need? Towards Scaling Laws of Compound Inference Systems," arXiv:2403.02419 (Mar 2024). The performance of Vote and Filter-Vote "can first increase but then decrease" as LM calls grow, because more calls help on easy queries and hurt on hard ones. — [arXiv 2403.02419](https://arxiv.org/abs/2403.02419)
- Kapoor, Stroebl, Siegel, Nadgir, Narayanan, "AI Agents That Matter," arXiv:2407.01502 (Jul 2024). Agent benchmarks focus too narrowly on accuracy, so "SOTA agents are needlessly complex and costly." The authors argue for jointly optimizing cost and accuracy and for proper holdouts. — [arXiv 2407.01502](https://arxiv.org/abs/2407.01502)
- Wei Sun, "Decision-Centric Design for LLM Systems," arXiv:2604.00414 (Apr 1, 2026). The paper proposes "a decision-centric framework that separates decision-relevant signals from the policy that maps them to actions," so failures can be attributed to "signal estimation, decision policy, or execution." It unifies routing and adaptive inference and extends to sequential settings. Across 3 controlled experiments it "reduces futile actions, improves task success." (The search snippet attributed this to IBM Research; the arXiv metadata does not show an affiliation.) — [arXiv 2604.00414](https://arxiv.org/abs/2604.00414)
- Self-Refine (the canonical evaluator-optimizer loop): Madaan, Tandon, Gupta, Hallinan, Gao, Wiegreffe, Alon, Dziri et al., arXiv:2303.17651 (Mar 2023). The same LLM generates, critiques and refines, improving task performance by about 20% absolute on average across 7 tasks. — [arXiv 2303.17651](https://arxiv.org/abs/2303.17651)

### Inferences
- DSPy and LMQL type the *interface* of a generative call: signatures, and constraints on output. Our typed decision model types the *output as a distribution over declared options* and moves behavior into a pure rule. Dohan et al.'s probabilistic-program view is the closest theory ancestor of "belief as a first-class value."
- Chen et al. 2024 (non-monotone voting) and Kapoor et al. 2024 (complexity without gains) support our earlier findings that structure helps only conditionally.
- Wei Sun 2026 is the most direct prior statement of our "behavior lives in rules" principle and should be cited and contrasted. Their signals are not specifically typed beliefs from a decision model, and they do not use Anthropic's five structures **[inference from the abstract only]**.

## Q3. Model cascades and routing

### Takeaway
The cascade lineage runs from Viola–Jones (2001) to FrugalGPT, AutoMix, RouteLLM and cascade routing. The 2023–2026 theory (Jitkrittum et al. 2023; Dekoninck et al. 2024; Bouchard 2026) agrees that gains hinge on deferral-score quality. Bouchard 2026 finds two-model cascades help (+2.1 to 8.2 pp), but more depth almost never helps (no gain in 118 of 135 comparisons). This fits our finding that cascades mostly save cost.

### Cited Findings
- Paul Viola and Michael Jones, "Rapid Object Detection using a Boosted Cascade of Simple Features," CVPR 2001, vol. 1, pp. I-511–I-518, DOI 10.1109/CVPR.2001.990517 **[unverified: from memory; not fetched]**.
- FrugalGPT: Lingjiao Chen, Matei Zaharia, James Zou, arXiv:2305.05176 (May 2023); later TMLR **[venue unverified]**. It names three strategies: prompt adaptation, LLM approximation, LLM cascade. FrugalGPT "can match the performance of the best individual LLM (e.g. GPT-4) with up to 98% cost reduction or improve the accuracy over GPT-4 by 4% with the same cost." — [arXiv 2305.05176](https://arxiv.org/abs/2305.05176)
- AutoMix: Aggarwal, Madaan, Anand, Potharaju, Mishra, Zhou, Gupta, Rajagopal et al., arXiv:2310.12963, NeurIPS 2024. It combines few-shot self-verification of the small model's answer with a POMDP router, "reducing computational cost by over 50% for comparable performance" across 5 LMs and 5 datasets. — [arXiv 2310.12963](https://arxiv.org/abs/2310.12963)
- RouteLLM: Ong, Almahairi, Wu, Chiang, Wu, Gonzalez, Kadous, Stoica, arXiv:2406.18665 (Jun 2024); ICLR 2025 **[venue unverified]**. Routers trained on human preference data choose strong vs weak models, reduce cost "by over 2 times in certain cases" without quality loss, and still work when the model pair changes. — [arXiv 2406.18665](https://arxiv.org/abs/2406.18665)
- RouterBench: Hu, Bieker, Li, Jiang, Keigwin, Ranganath, Keutzer, Upadhyay, arXiv:2403.12031 (Mar 2024). A benchmark of over 405k inference outcomes for evaluating routers. — [arXiv 2403.12031](https://arxiv.org/abs/2403.12031)
- Jitkrittum, Gupta, Menon, Narasimhan, Rawat, Kumar, "When Does Confidence-Based Cascade Deferral Suffice?" arXiv:2307.02764, NeurIPS 2023. Confidence-based deferral (max softmax) "often works remarkably well" even though it ignores downstream models. Post-hoc deferral beats it when (i) downstream models are specialists, (ii) labels are noisy, or (iii) train and test distributions shift. — [arXiv 2307.02764](https://arxiv.org/abs/2307.02764)
- Gupta, Narasimhan, Jitkrittum, Rawat, Menon, Kumar, "Language Model Cascades: Token-level uncertainty and beyond," arXiv:2404.10136 (Apr 2024). Sequence-level uncertainty has a length bias, and token-level uncertainty aggregation does better for generative cascades. — [arXiv 2404.10136](https://arxiv.org/abs/2404.10136)
- Dekoninck, Baader, Vechev, "A Unified Approach to Routing and Cascading for LLMs," arXiv:2410.10347 (Oct 2024). Derives an optimal cascading strategy, proves an existing routing strategy optimal and proposes "cascade routing." It identifies "good quality estimators as the critical factor." — [arXiv 2410.10347](https://arxiv.org/abs/2410.10347)
- Dylan Bouchard, "Is Escalation Worth It? On the Depth of LLM Cascades," arXiv:2605.06350v2 (May 7, 2026). v1 was titled "Is Escalation Worth It? A Decision-Theoretic Characterization of LLM Cascades." First-order optimality makes "the ratio of expected accuracy gain to expected downstream cost… equal across deferral boundaries." An identity splits the gain of score-based over random escalation into two AUROC terms. Two-model cascades improve mean test accuracy over single-model selection by 2.1–8.2 pp. More than two models gives no improvement in 118 of 135 comparisons and adds at most 0.43 pp. Depth helps only when scores separate the *current* model's correctness, and not when the scores reflect query difficulty shared across models. — [arXiv 2605.06350](https://arxiv.org/abs/2605.06350)
- Varun Kotte, "UCCI: Calibrated Uncertainty for Cost-Optimal LLM Cascade Routing," arXiv:2605.18796 (May 11, 2026). Maps token-level margin uncertainty to per-query error probability via isotonic regression, then picks the escalation threshold by constrained cost minimization. Threshold policies on the calibrated score are cost-optimal under 3 assumptions, and calibration ECE has O(n^{-1/3}) sample complexity. On a production NER workload of 75,000 queries (4B → 12B models, H100), it cuts cost by 31% (95% CI 27–35%) at micro-F1 0.91 and reduces ECE from 0.12 to 0.03. It beats entropy thresholding, split-conformal routing and a FrugalGPT-style threshold. — [arXiv 2605.18796](https://arxiv.org/abs/2605.18796)
- Yasmin Moslem, John D. Kelleher, "Dynamic Model Routing and Cascading for Efficient LLM Inference: A Survey," arXiv:2603.04445, TMLR 2026. Covers routing by query difficulty, human preferences, clustering, uncertainty quantification, RL, multimodality and cascading. Its framework classifies systems by *when* decisions are made, *what* information is used and *how* they are computed, and notes practical systems "are often compositional." — [arXiv 2603.04445](https://arxiv.org/abs/2603.04445)
- Chang, Kwon, Lee, Verma, "CascadeDebate: Multi-Agent Deliberation for Cost-Aware LLM Cascades," arXiv:2604.12262 (Apr 2026). Puts ensemble deliberation at each tier's escalation boundary, with humans as the final fallback. Up to +26.75% over single-model cascades, and "an online threshold optimizer proves essential" (20.98–52.33% relative improvement over fixed policies). — [arXiv 2604.12262](https://arxiv.org/abs/2604.12262)
- Jung, Brahman, Choi, "Trust or Escalate: LLM Judges with Provable Guarantees for Human Agreement," arXiv:2407.18370 (Jul 2024). Selective evaluation plus "Cascaded Selective Evaluation" guarantees a user-specified human-agreement level. With models such as Mistral-7B it "guarantees over 80% human agreement with almost 80% test coverage" on a Chatbot Arena subset where GPT-4 alone rarely reaches 80%. — [arXiv 2407.18370](https://arxiv.org/abs/2407.18370)

### Inferences
- Bouchard 2026 and UCCI 2026 are the closest recent matches for our cascade and threshold claims. Both treat the threshold (rule) as the main control knob and calibrated confidence as the precondition. Bouchard's "shared difficulty" result is effectively a correlated-errors argument against deep cascades, which supports our panel-independence finding.
- CascadeDebate's result that threshold optimization beats fixed policies supports our "abstention thresholds are the dominant lever."
- In our vocabulary, a cascade is a chained structure whose rule is "act if max belief ≥ τ, else defer." Most of this literature fuses rule and model into one "router," while we keep them separate.

### Gaps
- Viola–Jones and the venues for FrugalGPT and RouteLLM were not verified this session.

## Q4. Ensembles, voting, juries and correlated errors

### Takeaway
Self-consistency and PoLL show that aggregation helps, and PoLL ties the gains to *disjoint model families*. Kim et al. (ICML 2025) and Goel et al. (2025) show errors are strongly correlated across LLMs and grow more similar with capability. This directly supports our finding that same-family panels are not independent.

### Cited Findings
- Self-consistency: Xuezhi Wang, Jason Wei, Dale Schuurmans, Quoc Le, Ed Chi, Sharan Narang, Aakanksha Chowdhery, Denny Zhou, arXiv:2203.11171, ICLR 2023. Sample diverse reasoning paths and take the majority answer. Gains: GSM8K +17.9%, SVAMP +11.0%, AQuA +12.2%, StrategyQA +6.4%, ARC-challenge +3.9%. — [arXiv 2203.11171](https://arxiv.org/abs/2203.11171)
- PoLL: Pat Verga, Sebastian Hofstätter, Sophia Althammer, Yixuan Su, Aleksandra Piktus, Arkady Arkhangorodsky, Minjie Xu, Naomi White et al. (9 authors; Cohere), "Replacing Judges with Juries: Evaluating LLM Generations with a Panel of Diverse Models," arXiv:2404.18796 (Apr 2024). Across 3 judge settings and 6 datasets, a panel of smaller models "outperforms a single large judge, exhibits less intra-model bias due to its composition of disjoint model families," at "over seven times less expensive." — [arXiv 2404.18796](https://arxiv.org/abs/2404.18796)
- LLM-as-a-judge: Lianmin Zheng, Wei-Lin Chiang, Ying Sheng, Siyuan Zhuang, Zhanghao Wu, Yonghao Zhuang, Zi Lin, Zhuohan Li et al., "Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena," arXiv:2306.05685, NeurIPS 2023 Datasets & Benchmarks. Documents position, verbosity and self-enhancement biases. GPT-4 judges reach "over 80% agreement" with humans, the same as human–human agreement. — [arXiv 2306.05685](https://arxiv.org/abs/2306.05685)
- Correlated errors: Elliot Kim, Avi Garg, Kenny Peng, Nikhil Garg, "Correlated Errors in Large Language Models," arXiv:2506.07962, ICML 2025. Covers over 350 LLMs. "On one leaderboard dataset, models agree 60% of the time when both models err." Shared architecture and provider drive correlation, but "larger and more accurate models have highly correlated errors, even with distinct architectures and providers." The paper shows effects on LLM-as-judge and hiring (algorithmic monoculture). — [arXiv 2506.07962](https://arxiv.org/abs/2506.07962)
- Shashwat Goel, Joschka Strüber, Ilze Amanda Auzina, Karuna K Chandra, Ponnurangam Kumaraguru, Douwe Kiela, Ameya Prabhu, Matthias Bethge et al. (9 authors), "Great Models Think Alike and this Undermines AI Oversight," arXiv:2502.04313 (Feb 2025). Proposes CAPA, an error-overlap similarity metric. Judges favor models similar to themselves, and "model mistakes are becoming more similar with increasing capabilities." (The brief's "Kim et al. 2025" is the ICML paper above; "Great models think alike" is Goel et al.) — [arXiv 2502.04313](https://arxiv.org/abs/2502.04313)
- Chen et al. 2024 (above) show majority-vote accuracy can fall as calls increase when queries are hard. — [arXiv 2403.02419](https://arxiv.org/abs/2403.02419)
- 2026: Alotaibi, Jabbar, Al-Azani, Ahmed, "Layered LLM Defenses as an Ensemble…" arXiv:2608.28327 (Aug 2026). Stacked defenses compound only if members "fail on different inputs," and the paper measures failure correlation between layers. — [arXiv 2608.28327](https://arxiv.org/abs/2608.28327)

### Inferences
- PoLL's benefit relies on cross-family diversity. Kim et al.'s 60% conditional error agreement quantifies why same-family panels add little. Our "panels of one model family are not independent" result is consistent with both and extends them to belief-level aggregation.
- Self-consistency is "voting" in Anthropic's sense, within a single model, so its gains come from sampling diversity rather than model diversity.

## Q5. Confidence from LLMs: P(True), verbalized confidence, logprobs and RLHF calibration

### Takeaway
Base or pre-trained LMs are well calibrated on properly formatted MC/TF questions (Kadavath 2022). RLHF and RLVR degrade token-probability calibration (Tian 2023; Leng 2024; Yaldiz 2026). Which elicitation is best is contested: Tian (2023) finds verbalized confidence better for RLHF models, Xiong (ICLR 2024) finds it overconfident, and Tao et al. (2025, 80 models) favor linguistic verbal uncertainty. A 2026 study (Sun et al.) adds that verbalized scores rank well but are too coarse to threshold finely, which matters for rule-based abstention.

### Cited Findings
- Saurav Kadavath, Tom Conerly, Amanda Askell, Tom Henighan, Dawn Drain, Ethan Perez, Nicholas Schiefer, Zac Hatfield-Dodds et al. (36 authors), "Language Models (Mostly) Know What They Know," arXiv:2207.05221 (Jul 2022). "Larger models are well-calibrated on diverse multiple choice and true/false questions when they are provided in the right format." P(True) self-evaluation shows good calibration and scaling. P(IK) partially generalizes but is poorly calibrated on new tasks. — [arXiv 2207.05221](https://arxiv.org/abs/2207.05221)
- Katherine Tian, Eric Mitchell, Allan Zhou, Archit Sharma, Rafael Rafailov, Huaxiu Yao, Chelsea Finn, Christopher D. Manning, "Just Ask for Calibration…," arXiv:2305.14975, EMNLP 2023. For RLHF models (ChatGPT, GPT-4, Claude), "verbalized confidences… are typically better-calibrated than the model's conditional probabilities" on TriviaQA, SciQ and TruthfulQA, "often reducing the expected calibration error by a relative 50%." — [arXiv 2305.14975](https://arxiv.org/abs/2305.14975)
- Miao Xiong, Zhiyuan Hu, Xinyang Lu, Yifei Li, Jie Fu, Junxian He, Bryan Hooi, "Can LLMs Express Their Uncertainty? An Empirical Evaluation of Confidence Elicitation in LLMs," arXiv:2306.13063, ICLR 2024. Uses a framework of prompting, sampling and aggregation. LLMs verbalizing confidence "tend to be overconfident." Calibration and failure prediction improve with scale, and consistency across samples helps. — [arXiv 2306.13063](https://arxiv.org/abs/2306.13063)
- Tony Z. Zhao, Eric Wallace, Shi Feng, Dan Klein, Sameer Singh, "Calibrate Before Use: Improving Few-Shot Performance of Language Models," arXiv:2102.09690, ICML 2021. Label bias toward answers placed late in the prompt or common in pretraining. Contextual calibration with a content-free input ("N/A") improves average accuracy "up to 30.0% absolute" and reduces prompt variance. — [arXiv 2102.09690](https://arxiv.org/abs/2102.09690)
- GPT-4 Technical Report (OpenAI, arXiv:2303.08774, Mar 2023). The report's calibration figure shows the pre-trained model well calibrated on MMLU and post-training (RLHF) reducing calibration **[the specific figure content is from memory; the abstract does not state it]**. — [arXiv 2303.08774](https://arxiv.org/abs/2303.08774)
- Jixuan Leng, Chengsong Huang, Banghua Zhu, Jiaxin Huang, "Taming Overconfidence in LLMs: Reward Calibration in RLHF," arXiv:2410.09724 (Oct 2024). RLHF leads to verbalized overconfidence, and PPO reward models are biased toward high-confidence scores. Proposes PPO-M and PPO-C. — [arXiv 2410.09724](https://arxiv.org/abs/2410.09724)
- Linwei Tao, Yi-Fan Yeh, Minjing Dong, Tao Huang, Philip Torr, Chang Xu, "Revisiting Uncertainty Estimation and Calibration of Large Language Models," arXiv:2505.23854 (May 2025). Covers 80 models (0.6B–671B) on MMLU-Pro. Linguistic verbal uncertainty (LVU) "consistently outperforms" token-probability (TPU) and numerical verbal uncertainty. "High accuracy does not imply reliable uncertainty," and "good calibration does not necessarily translate to effective error ranking." — [arXiv 2505.23854](https://arxiv.org/abs/2505.23854)
- Ao Sun, Tian Sun, Jiaxing Geng, "The Score Granularity Gap in Black-Box LLM Classification: A Comparative Study of Confidence Constructions," arXiv:2606.22179 (Jun 2026). Compares 7 confidence constructions on 25 model–dataset pairs (9 LLMs, 3 benchmarks). Single-shot verbalized confidence "ranks cases surprisingly well, yet takes only a handful of distinct values," so it offers only a few coarse thresholds. Multi-query aggregation "helps weak models but can degrade already-strong ones." — [arXiv 2606.22179](https://arxiv.org/abs/2606.22179)
- Duygu Nur Yaldiz, Evangelia Spiliopoulou, Zheng Qi, Siddharth Varia, Srikanth Doss, Nikolaos Pappas, "Balancing Classification and Calibration Performance in Decision-Making LLMs via Calibration Aware Reinforcement Learning," arXiv:2601.13284 (Jan 2026). RLVR "produces extremely overconfident models," and SFT is better calibrated. Decision tokens "do not carry confidence information." Calibration-aware RL reduces ECE by up to 9 points. — [arXiv 2601.13284](https://arxiv.org/abs/2601.13284)
- Survey: Jiahui Geng, Fengyu Cai, Yuxia Wang, Heinz Koeppl, Preslav Nakov, Iryna Gurevych, "A Survey of Confidence Estimation and Calibration in Large Language Models," arXiv:2311.08298 (Nov 2023). — [arXiv 2311.08298](https://arxiv.org/abs/2311.08298)

### Inferences
- Our "chat LLM read through next-token logprobs" is the TPU / conditional-probability channel that Tian 2023 and Yaldiz 2026 find miscalibrated after RLHF/RLVR. That is grounds for post-hoc calibration (temperature or isotonic, as in UCCI) before rules act on beliefs.
- Sun et al. 2026's granularity point argues for real-valued beliefs (logprobs or decision heads) over verbalized numbers whenever the rule is a threshold.
- The verbalized vs token-probability literature conflicts (Tian vs Xiong vs Tao). Present it as unresolved and setting-dependent.

## Q6. Zero-shot classification via NLI, universal classifiers, and option-order / label bias

### Takeaway
Our "open encoders" decision models descend from NLI-based zero-shot classification (Yin et al. 2019; Laurer et al. 2023) and GLiNER-style architectures (GLiNER 2023; GLiClass 2025). Option-order and label-token bias (Zhao 2021; Pezeshkpour & Hruschka 2023; Zheng et al. ICLR 2024) is a known failure mode of reading beliefs off option tokens.

### Cited Findings
- Wenpeng Yin, Jamaal Hay, Dan Roth, "Benchmarking Zero-shot Text Classification: Datasets, Evaluation and Entailment Approach," arXiv:1909.00161, EMNLP 2019. Unified 0Shot-TC datasets (topic, emotion, situation), the "label-fully-unseen" setting, and an entailment (NLI) approach. — [arXiv 1909.00161](https://arxiv.org/abs/1909.00161)
- Moritz Laurer, Wouter van Atteveldt, Andreu Casas, Kasper Welbers, "Building Efficient Universal Classifiers with Natural Language Inference," arXiv:2312.17543 (Dec 2023). NLI as a universal classification task. The classifier is trained on 33 datasets with 389 classes, improves zero-shot performance by 9.4%, and the older zero-shot models had been downloaded "more than 55 million times." — [arXiv 2312.17543](https://arxiv.org/abs/2312.17543)
- Urchade Zaratiana, Nadi Tomeh, Pierre Holat, Thierry Charnois, "GLiNER: Generalist Model for Named Entity Recognition using Bidirectional Transformer," arXiv:2311.08526 (Nov 2023); NAACL 2024 **[venue unverified]**. A compact bidirectional encoder extracts arbitrary entity types in parallel and outperforms ChatGPT and fine-tuned LLMs zero-shot. — [arXiv 2311.08526](https://arxiv.org/abs/2311.08526)
- Ihor Stepanov, Mykhailo Shtopko, Dmytro Vodianytskyi, Oleksandr Lukashov, Alexander Yavorskyi, Mykyta Yaroshenko, "GLiClass: Generalist Lightweight Model for Sequence Classification Tasks," arXiv:2508.07662 (Aug 11, 2025). Adapts GLiNER to sequence classification with efficiency comparable to embedding methods, plus zero-shot and few-shot flexibility, and adds PPO for multi-label training. It argues generative LLMs "suffer from inconsistent instruction following and computational inefficiency," and that cross-encoders must process text–label pairs sequentially. — [arXiv 2508.07662](https://arxiv.org/abs/2508.07662); model family on [Hugging Face](https://huggingface.co/knowledgator/gliclass-modern-large-v3.0)
- Pouya Pezeshkpour, Estevam Hruschka, "Large Language Models Sensitivity to The Order of Options in Multiple-Choice Questions," arXiv:2308.11483 (Aug 2023). A performance gap of "approximately 13% to 75%" when options are reordered. — [arXiv 2308.11483](https://arxiv.org/abs/2308.11483)
- Chujie Zheng, Hao Zhou, Fandong Meng, Jie Zhou, Minlie Huang, "Large Language Models Are Not Robust Multiple Choice Selectors," arXiv:2309.03882, ICLR 2024 Spotlight. Selection bias across 20 LLMs comes mainly from *token bias*, prior mass on option-ID tokens (A/B/C/D). PriDe debiasing estimates the prior by permuting options. — [arXiv 2309.03882](https://arxiv.org/abs/2309.03882)
- Zhao et al. 2021 (above) is the earliest of these on label and recency bias in label probabilities. — [arXiv 2102.09690](https://arxiv.org/abs/2102.09690)

### Inferences
- Encoders that score each option independently (NLI cross-encoders, and Verdict-MQ in Q8) remove option-order bias by construction. Logprob-read chat LLMs inherit Zheng et al.'s token bias unless options are permuted or debiased.

### Gaps
- GLiClass benchmark numbers were not extracted from the full text.

## Q7. Contamination and fresh-data / time-split evaluation

### Takeaway
LiveBench and LiveCodeBench answer contamination with continuously refreshed, release-dated questions. Sainz et al. and Xu et al. document why static benchmarks overstate performance. Time-split evaluation (questions dated after the model's cutoff) is the standard mitigation.

### Cited Findings
- Colin White, Samuel Dooley, Manley Roberts, Arka Pal, Ben Feuer, Siddhartha Jain, Ravid Shwartz-Ziv, Neel Jain et al. (18 authors), "LiveBench: A Challenging, Contamination-Limited LLM Benchmark," arXiv:2406.19314, ICLR 2025 Spotlight. Questions are frequently updated from recent sources (math competitions, arXiv papers, news, datasets) and scored automatically against objective ground truth, with no LLM judge. Top models score "below 70% accuracy." — [arXiv 2406.19314](https://arxiv.org/abs/2406.19314)
- Naman Jain, King Han, Alex Gu, Wen-Ding Li, Fanjia Yan, Tianjun Zhang, Sida Wang, Armando Solar-Lezama et al., "LiveCodeBench: Holistic and Contamination Free Evaluation of Large Language Models for Code," arXiv:2403.07974 (Mar 2024). Continuously collects LeetCode, AtCoder and CodeForces problems with release dates (400 problems from May 2023 to May 2024 at the time of writing), and evaluates 18 base and 34 instruction-tuned LLMs. Release dates enable contamination analysis, and the paper reports potential overfitting on HumanEval-style benchmarks. — [arXiv 2403.07974](https://arxiv.org/abs/2403.07974)
- Oscar Sainz, Jon Ander Campos, Iker García-Ferrero, Julen Etxaniz, Oier Lopez de Lacalle, Eneko Agirre, "NLP Evaluation in trouble: On the Need to Measure LLM Data Contamination for each Benchmark," arXiv:2310.18018 (Oct 2023). The arXiv comment says "Accepted at EMNLP2024-Findings." It is commonly cited as Findings of EMNLP 2023, so this conflicts; **check the ACL Anthology before citing**. The paper defines contamination levels and calls for per-benchmark contamination measurement. — [arXiv 2310.18018](https://arxiv.org/abs/2310.18018)
- Cheng Xu, Shuhao Guan, Derek Greene, M-Tahar Kechadi, "Benchmark Data Contamination of Large Language Models: A Survey," arXiv:2406.04244 (Jun 2024). Reviews benchmark data contamination and alternative assessment methods. — [arXiv 2406.04244](https://arxiv.org/abs/2406.04244)

### Inferences
- If our benchmark uses items dated after the models' cutoffs, cite LiveBench and LiveCodeBench as precedent for time-split design, and Sainz et al. for why it matters.

## Q8. 2026 work applying these ideas to typed decision models (flag only; another researcher covers TDMs in depth)

### Takeaway
An arXiv abstract search on "typed decision" / "Jev" / "OpenAI Decisions" turns up a burst of Sept–Oct 2026 TDM papers. Several apply exactly the systems ideas above: cascades and thresholds, decision models inside multi-agent workflows, TDMs as judges, fallback/abstention options and calibration benchmarks. Flagged here for the TDM researcher.

### Cited Findings
- Chen, Liu, An, Wang, Zhou, "System1-Arena: Which Decisions Can Be Left to System 1?" arXiv:2610.21244 (Oct 15, 2026). 92k questions, 105 tasks, 138 closed-loop environments, 30 models (7 closed LLMs, 13 open LLMs "read at the answer token," 10 System-1 models including Jev and the OpenAI Decisions API). The largest System-1 models match or exceed fast closed LLMs in non-agentic accuracy, with better calibration at one quarter of the latency, while a reasoning LLM is most accurate at about 70x the cost of a fast LLM. — [arXiv 2610.21244](https://arxiv.org/abs/2610.21244)
- Zhu, Feng, Han, Wang, Yang, Tang et al., "JevAgentHarness: Benchmarking, Deploying and Training Decision Models That Share Control with LLMs," arXiv:2610.21412 (Oct 2026). The best isolated-question decision model solved only 69.5% of agent tasks, and delegating tool choices "without a fitted confidence threshold" lowered success by 19.0 points. They fit per-choice thresholds and defer to the LLM below them. This strongly echoes our "thresholds are the dominant lever." — [arXiv 2610.21412](https://arxiv.org/abs/2610.21412)
- Wang, Zhou, Lou, Li, "Jev-LiteMAS: Separating Decisions from Generation in Multi-Agent Workflows," arXiv:2610.21411 (Oct 2026). Routing and review take 31.7–43.5% of generative-LLM tokens in 3 MAS frameworks. Jev selects experts (orchestrator-like) and screens artifacts (evaluator-like), escalating flagged ones to an LLM. — [arXiv 2610.21411](https://arxiv.org/abs/2610.21411)
- Lukassen, Weisser, Silbersdorff, "Cheap, Consistent, Calibrated, but Biased? Typed Decision Models as Judges," arXiv:2610.18122 (Oct 2026). 8 TDMs vs 7 LLM judges on CALM bias tests. Every TDM is biased in 3–8 of 12 tests, all 8 flip verdicts under position swap, and emotional-tone rewriting drops a typical TDM from 99% to 42%. TDMs are 37x cheaper than 2026 LLM judges. — [arXiv 2610.18122](https://arxiv.org/abs/2610.18122)
- Sharma, Duncan, Marceau Caron, Vollmer, "TypedBench: A Benchmark for Calibration, Framing Sensitivity, and Cost in System One Decision Models," arXiv:2610.11392 (Oct 2026). Selective prediction, ordinal proper scoring rules and realized cost under asymmetric cost matrices, comparing a hosted model, an open encoder and open decoders (0.8B–9B). Explicitly frames software acting via "thresholds, cost-weighted choices, and escalation rules." — [arXiv 2610.11392](https://arxiv.org/abs/2610.11392)
- Xie, Zhu, Liu, Zhang, Xiong, Liu, "Lost in the Fallback: How Reliably Do Typed Decision Models Use Fallback Options?" arXiv:2610.19856 (Oct 2026). Fallback (defer or abstain) options are unreliable, and logically equivalent fallback rules produce disagreement.
